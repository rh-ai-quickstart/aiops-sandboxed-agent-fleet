You understand the pieces — now **play with the whole control plane like an operator** before you build for real: observe it, govern it, expose it, using the `openshell` CLI. We'll create a **throwaway sandbox** just to poke at (no OpenClaw, no model — that's Part IV). By the end you'll have touched every part of OpenShell. (All of this runs in the lab shell against your live gateway.)

Spin up the throwaway sandbox. `--from` picks the sandbox image — the pinned OpenClaw image (`$OPENCLAW_SANDBOX_IMAGE`, already pulled on the nodes; this lab won't actually run OpenClaw). `--policy` is mandatory in practice: a sandbox without a policy never becomes Ready. `--detach -- sleep infinity` gives the box a main process that keeps it alive, and returns your prompt as soon as it's running (a command that exits, like `true`, would leave the sandbox *Completed*). `--no-tty` runs it non-interactively.

```bash
openshell sandbox create --name lab --no-tty \
  --from "$OPENCLAW_SANDBOX_IMAGE" \
  --policy ~/nemoclaw-openshift-launchable/policies/openclaw-sandbox.yaml \
  --detach -- sleep infinity
```

List your sandboxes:

```bash
openshell sandbox list
```

## 1. Is the gateway healthy?

```bash
openshell status
```

`Status: Connected` + a version is the control plane answering.

## 2. Inspect a sandbox

```bash
openshell sandbox get lab
```

Note the **Phase**, the **Policy source** (sandbox vs gateway-global), and the **Revision** — every policy change bumps it. The effective policy is printed inline.

## 3. The audit trail — `logs`

This is OpenShell's observability: every gateway + sandbox action, structured. Watch the bootstrap you learned about actually happen:

```bash
openshell logs lab --source gateway
```

You'll see `Creating sandbox in Kubernetes` and `issued generation-bound gateway sandbox JWT` — the sandbox's identity being minted, the handshake from the architecture lesson. Filter and stream:

```bash
openshell logs lab --source sandbox --level debug
```

Now stream it live — this one **keeps running** and follows new events:

```bash
openshell logs lab --tail
```

When you're done watching, press <kbd>Ctrl-C</kbd> in the shell to stop the tail and get your prompt back (it blocks until you do).

<Callout type="note" title="This is the SIEM feed">
Each entry is an OCSF-style security event. In production you stream these to your SIEM — every allow/deny, every policy change, every exec, attributable to a sandbox.
</Callout>

## 4. Govern it — `policy`

See the effective policy and its history:

```bash
openshell policy get lab        # the policy currently in force
```

```bash
openshell policy list lab       # revision history, with a status per revision
```

Each policy change is a **revision**. In the history, a revision's **Status** is `Pending` until the sandbox's supervisor confirms it has loaded that revision — then it flips to `Loaded` (an older one becomes `Superseded`; a revision the supervisor rejects shows `Failed`). `policy get` always shows the policy *currently compiled and in force*. Our `lab` box has a live supervisor (its main process is still running), so you'll watch the first revision go `Loaded` within seconds.

`openshell policy` also does `set` / `update` (hot-reload egress on a running sandbox — no restart; `--wait` blocks until the supervisor has loaded it). That's the audit→enforce loop from the policy lesson, live.

## 5. Where does a model key come from? — `provider`

```bash
openshell provider list
```

A **provider** is a credential the gateway holds (your inference key, a GitHub token, …), typed by a **provider profile** that says which host it may be sent to and which binaries may send it. Attach a provider to a sandbox (`sandbox create --provider …` or `openshell sandbox provider attach`) and the sandbox only ever sees a **placeholder**; the supervisor swaps in the real secret on egress to the allowed host. Our `lab` box has none attached:

```bash
openshell sandbox provider list lab
```

That's exactly how you'll give your own agent a model in Part IV — without ever handing it the key.

## 6. Expose a port — `forward` / `service`

If a sandbox serves HTTP, reach it without `oc`:

```bash
openshell service list           # exposed sandbox services
openshell forward list           # active port-forwards
```

(You'll use `openshell forward start` for real in *Open the Agent UI* to expose your agent's Control UI.)

```bash
openshell sandbox delete lab
```
